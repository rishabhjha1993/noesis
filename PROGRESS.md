# Noesis Progress

## Current Branch

`product/noesis-vnext`

## Current Product State

The legacy Noesis experience works as a standalone full-stack Node service. The React upload/result UI, Express API, asynchronous analysis jobs and polling, deterministic evidence computation, OpenAI analysis pipeline, cache support, and evaluation infrastructure are preserved. Platform-independent production serving, minimum public-safety controls, instrumentation, and evaluation infrastructure are checkpointed in Git and deployed. Discovery Engine V1 exists as the parallel `/discovery-lab` path and has been qualitatively evaluated on Noordoostpolder, Minard, Pantheon, and Chuquicamata, but has not been deployed. `/discovery-lab` retains the immutable `V1 frozen baseline` sourced from historical checkpoint `3a0bca12` plus the prior experimental variants. `V2 Hybrid — production candidate` v3 is now the frozen launch intelligence architecture, accepted on the golden Noordoostpolder run. The next phase is product shipping rather than architecture optimization.

## Current Milestone

Noesis V2 Hybrid v3 is formally frozen as the launch intelligence baseline at commit `bfc83f96ec124bb759f7a11f4f1543f659322ace` and annotated tag `noesis-v2-hybrid-v3-launch-baseline`. The architecture is Sol-medium visual Stage 1 → one Luna-medium first-party OpenAI web-search operation per gated candidate at concurrency three → multimodal Sol-medium final synthesis with the original high-detail image → unchanged deterministic validation. It has no standalone identity-verification call and never calls DeepSeek; relevant Stage-1 identity hypotheses remain candidate-local unverified search leads, and exact identity may become factual only through applicable validated candidate research. Golden Noordoostpolder run `74f39a17-7f9b-4cc9-8482-857f7418566c` answered 4/5 research candidates, safely degraded malformed `cand_02`, and produced three validated researched discoveries in `86.181s` for `$0.2445254` known cost. Human review accepted the output as clearing the current launch-quality bar. Future intelligence changes require evidence from real user failures or clear cross-visual evaluation regressions.

- The app runs without Postgres, with an explicit warning and no persistent cache; setting `DATABASE_URL` restores persistent cache behavior.
- `OPENAI_API_KEY` is configured in Railway and must remain server-only.
- `NOESIS_ACCESS_CODE` is optional. Without it, production remains public but analysis starts are rate-limited.
- Legacy prompts, model allocation, reasoning levels, token limits, schemas, and analysis behavior remain unchanged. V1 changes only the parallel Discovery prompts/contracts needed for verified identity context.
- Discovery quality must remain visually triggered and return the user to the uploaded image.
- Discovery retains exactly three conceptual stages: Sol vision grounding/question formation, selectively gated Terra web research, and text-only Sol discovery synthesis. Identity verification is a conditional substep inside Stage 2, not a fourth stage or agent.
- All three Discovery stages use medium reasoning. Stage 2 receives only Stage 1-approved text questions and never receives the image.
- Discovery V1 uses the independent `discovery-engine-v1` in-memory cache identity and cannot collide with V0 or legacy analysis cache entries.
- `/discovery-lab` remains outside normal public navigation and does not replace `/`.
- The copied eval JSON reuses the validated Discovery run structure, adds job/cache identity, and omits reasoning-token counts and internal-only fields.
- The first evidence-backed V1 hypothesis is narrow: Stage 1 already notices valuable image-specific questions, while Stage 2 often lacks verified entity, location, or object identity needed to research those questions safely and efficiently.
- Identity resolution remains a conditional substep inside Stage 2 and may only support questions already triggered by visible evidence.
- V1-family identity resolution runs once when either a Stage-1 identity hypothesis or any surviving identity-dependent candidate exists, and is skipped when neither exists. Terra receives only a compact text projection of validated/reconciled Stage-1 evidence; hypotheses are optional tentative leads rather than constraints. Verified identity applies only to candidates marked `identity_context_needed`; unverified/conflicted identity is withheld from candidate research and Stage 3.
- Shared typography and generic similarity are explicitly insufficient verification bases; verified identity requires validated sources and at least one stronger exact-match basis.
- Failed Discovery jobs expose only a sanitized diagnostic projection to the browser. Raw provider error details and server-only stacks remain in redacted structured logs; prompts, request bodies, secrets, images, and reasoning-token breakdowns are not returned.
- Failure observability is measurement-only: V1 prompts, models, reasoning levels, research gate, ranking, cache identity/behavior, and successful result contracts remain unchanged.
- `discovery-engine-v1-frozen-3a0bca12` is the immutable quality ruler for future experiments. The mutable `discovery-engine-v1` path is experimental and must not be used as a historical baseline. Economic improvements do not pass if visual grounding, usefulness, unsupported-claim rate, research usefulness, source integrity, or existing evaluation dimensions regress against the frozen ruler.

## Pre-Tester Identity-Resolution Strengthening (bounded, last authorized intelligence change before controlled testing)

Cross-domain evaluation of the frozen V2 Hybrid v3 baseline found a narrow, repeated failure mode distinct from Stage-1 quality: on Pentium die and Sakhalin, Stage 1 correctly grounded a strong visual question and a relevant identity hypothesis, but the existing candidate-local Luna research call treated that hypothesis as optional context rather than an explicit first responsibility. Luna stayed safely cautious and answered generically (or returned insufficient) instead of first attempting to establish or reject the exact identity with distinguishing evidence, so a stronger identity-specific discovery (Sakhalin's sea-ice regime, the Pentium II Dixon L2 cache) was never reachable even when the underlying research operation could plausibly have resolved it.

The bounded fix touches only `V2_HYBRID_RESEARCH_INSTRUCTIONS` and the per-candidate unverified-lead context string in `artifacts/api-server/src/lib/discoveryHybridV2.ts`. When a candidate has a relevant Stage-1 identity hypothesis, the existing Luna call is now explicitly instructed to first attempt to establish or reject that exact identity (ESTABLISHED / UNRESOLVED / CONTRADICTED), using evidence that ties this candidate's own visible clues to the proposed identity and distinguishes it from plausible lookalikes, before answering the approved question; a source that merely discusses the proposed subject in general, or "looks similar to X," is explicitly called out as insufficient. UNRESOLVED/CONTRADICTED conclusions must not be promoted to fact and must fall back to a safely supported generic answer or INSUFFICIENT, matching the existing ANSWERED/INSUFFICIENT contract. Identity-independent candidates are unaffected.

Architecture is explicitly unchanged: no new model/API call, no standalone identity stage, no DeepSeek, no second research round, no batching, no agent loop, unchanged Stage 1/Stage 3/final-validation/model/reasoning/concurrency (still `gpt-5.6-luna` medium, concurrency 3), and no change to the public Discovery output contract — the existing free-text `finding`/`status`/`sources` research-result fields already carry the ESTABLISHED/UNRESOLVED/CONTRADICTED conclusion without a schema change. `/see`, `/discovery-lab`, and legacy `/` were not touched.

## Pre-Tester Stage-1 Identity-Lead Recall (bounded upstream follow-up to `cd4b1c3`)

The first fresh post-`cd4b1c3` Sakhalin replay exposed an upstream gap the downstream fix could not reach: Stage 1 returned `identity_hypotheses: []` even though three candidates were `identity_context_needed: true` and their rationales said geography would unlock the answer, so the new candidate-local ESTABLISHED/UNRESOLVED/CONTRADICTED behavior was never exercised (4 candidates → 0 answered / 4 insufficient, no place-specific discovery). An earlier run of the same image had produced a `Sakhalin Island and adjacent waters` lead at 0.68 confidence, so Sol can form the lead but does not do so reliably on the launch path.

Root cause is structural, not stochastic: V2 Hybrid inherited the immutable frozen-V1 Stage-1 prompt (`FROZEN_V1_STAGE1_PROMPT`, `3a0bca12`, marked DO NOT MODIFY) via `usesFrozenV1Semantics`, so the launch path never received the identity-recall guidance the mutable `STAGE1_PROMPT` already carries, and its only identity wording is the oldest, most omission-biased paragraph ("optionally propose … return an empty array … do not identify merely because naming might be interesting"). That conservatism predates the `cd4b1c3` verifier contract, under which Stage 1 no longer needs to suppress a plausible moderate-confidence lead because Luna now establishes or rejects it.

The bounded fix forks a V2-owned Stage-1 prompt. `V2_HYBRID_STAGE1_PROMPT` in `artifacts/api-server/src/lib/discoveryHybridV2.ts` is derived from `FROZEN_V1_STAGE1_PROMPT` by replacing only the single conservative identity paragraph (via `String.replace` of the exact frozen paragraph, so the vision/region/candidate contract stays byte-identical) with recall-oriented guidance: after forming candidates, review every `identity_context_needed` candidate and, when the visible evidence suggests a plausible exact identity, emit the single best identity as an UNVERIFIED VISUAL LEAD even at moderate confidence, `verification_would_help: true`, linked to the relevant question/region ids, because downstream research will establish or reject it so uncertainty must not cause omission. ## Pre-Tester ESTABLISHED Evidence Bar (bounded safety follow-up to `cd4b1c3` / `a6c7198`)

Controlled replays after `a6c7198` split into a win and a safety failure. A snow-covered peninsula (we had mislabelled it Sakhalin) replayed as a success: Stage 1 proposed `Kamchatka Peninsula, Russia` at 0.82, Luna established it inside candidate-local research, and the final output carried strong place-specific discoveries (Kuril–Kamchatka volcanic arc, coastal ice, orographic cloud interaction). The Stage-1 recall change is validated and stays.

The next replay — an Intel **Pentium II Dixon** die shot — exposed a downstream safety leak. Stage 1 behaved correctly, surfacing `Intel Celeron / Mendocino core` at 0.54 as an explicitly unverified lead. But candidate-local Luna, for one question, declared the identity ESTABLISHED ("the exact die-photo set is labeled as such") on the strength of a **Wikimedia Commons category page** (`Category:Intel microprocessor dies`) plus generic architecture facts, and the final Sol then asserted the false discovery "the right third is Mendocino's on-die L2 cache" (128 KB). The real die is Dixon. This is exactly the leak the two-part identity system is meant to prevent: unverified Stage-1 lead → Luna wrongly declares ESTABLISHED → false exact identity in final output. The run used 16 web searches (one candidate 8, ~$0.092) at ~$0.351 / ~109s, so the defect is the evidence standard, not the search budget.

Root cause is the ESTABLISHED evidence bar inside the existing Luna call. Every other layer behaved as designed: source validation is URL-ownership only (a genuinely-cited category-page URL passes; `discoveryPipeline.ts:1043-1078`, `discoveryContracts.ts:630-682`), the result schema carries ESTABLISHED/UNRESOLVED/CONTRADICTED only as free text in `finding`, and the final Sol faithfully consumed Luna's "established" claim. The `cd4b1c3` instruction forbade "a source that merely discusses X in general" but never forbade treating category/gallery/list/search pages as same-object identification, never required ruling out the closest plausible alternative (Dixon vs Mendocino share a family-level die layout), and never defined a concrete ESTABLISHED bar.

The bounded fix touches only `V2_HYBRID_RESEARCH_INSTRUCTIONS` in `artifacts/api-server/src/lib/discoveryHybridV2.ts`, additively. It defines a two-route ESTABLISHED bar — (A) direct same-object evidence (a source identifying the same depicted object/photo/die/map/figure with matching distinguishing details) or (B) discriminative triangulation (multiple independent attributes that jointly separate the identity from its closest plausible alternatives); below the bar the conclusion is UNRESOLVED. It names category/gallery/list/index/search-result "contains an example of X" pages as never sufficient for same-object identity (membership is plausibility, not identification), requires naming and ruling out the nearest plausible alternative before ESTABLISHED, keeps generic architectural facts conditional and non-promoting, and reaffirms CONTRADICTED when reliable evidence identifies the object differently. This preserves the asymmetry: Kamchatka's visible evidence is intrinsically discriminative (few lookalikes) and corroborated; Mendocino's is family-level with category-page sources, so it falls to UNRESOLVED.

Architecture is explicitly unchanged: instruction text only — no schema, no new/second call, no identity stage, no judge, no domain allowlist, unchanged models/reasoning (`gpt-5.6-luna` medium), concurrency (3), search budget, final-Sol architecture, deterministic validation, and Stage 1 (`a6c7198` untouched). No cache-revision bump is needed because Stage-1 output and the research-result schema are unchanged; `V2_HYBRID_CACHE_REVISION` stays `v2-hybrid-v4`. `/see`, `/discovery-lab`, and legacy `/` were not touched. A focused instruction-contract test was added to `evals/tests/discoveryHybridV2.test.ts` (asserts the two-route bar, the category-page rule, the close-alternative requirement, and the conditional/contradiction wording); the existing behavioral A–E tests (established flows, unresolved/contradicted not promoted, identity-independent unchanged, source-ownership strict) remain green. Mocked tests intentionally verify only the instruction contract and downstream safety invariants — the emergent "category page ≠ established" behavior is provable only by the real Dixon replay. Full suite 183/183, typecheck, build, and prettier passed. No paid model, API, or web-search call was made during implementation or verification.

Freezing `a6c7198` is blocked on this fix: the Dixon leak is a systematic false-identity mechanism with no existing deterministic backstop. Five real (paid) replays remain for the user, Dixon first: Pentium II Dixon (primary safety — Mendocino must stay an unverified lead; final must never assert Mendocino/128 KB L2 as fact; UNRESOLVED-and-generic is a pass), Kamchatka (identity-win regression — must still establish), Noordoostpolder and Korean Peninsula (regression controls), and one ambiguous negative control (no fabricated identity). Freeze and ship only if Dixon is safe, Kamchatka is preserved, the regression controls hold, the negative control stays clean, and there is no cost/latency blowout or source-integrity loss.
