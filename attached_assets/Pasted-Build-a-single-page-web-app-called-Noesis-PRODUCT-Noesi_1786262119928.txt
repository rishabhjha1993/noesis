Build a single-page web app called Noesis.

PRODUCT
Noesis helps users understand complex visuals by teaching them how to read the visual itself, step by step.

The eventual experience will be:

Upload image
→ understand what kind of visual it is
→ identify its central question and big takeaway
→ guide the user through 4–6 important regions in a deliberate sequence
→ visually highlight relationships between regions
→ end with the overall insight

IMPORTANT FOR THIS FIRST BUILD:
DO NOT connect any AI or external API yet.
Use mocked data only.
I want the complete frontend interaction working reliably before we add GPT.

TECH
Use Next.js + React + TypeScript + Tailwind.

Use a modular structure:

app/
  page.tsx
  layout.tsx
  globals.css

components/
  UploadScreen.tsx
  LoadingScreen.tsx
  ResultScreen.tsx
  VisualCanvas.tsx
  Hotspot.tsx
  WalkthroughPanel.tsx
  ProgressControls.tsx

lib/
  types.ts
  mockAnalysis.ts

Keep app/page.tsx mainly responsible for top-level state and screen transitions.
Do NOT put the entire app into one giant component.

BUILD THESE THREE STATES:

1. UPLOAD SCREEN

Show:

NOESIS

"Understand complex visuals, step by step."

Add:
- drag-and-drop image upload
- choose-file button
- accept PNG, JPG, JPEG and WebP
- after selection, show the uploaded image preview
- button: "X-Ray this visual"

Keep the design serious, clean and visually sophisticated.
Do not make it look gamified.

2. LOADING STATE

After clicking "X-Ray this visual", briefly show:

Reading the visual...
Finding the important parts...
Building your walkthrough...

For now use an artificial 2–3 second delay.

3. RESULT SCREEN

Desktop layout:

LEFT:
uploaded image

RIGHT:
analysis / walkthrough panel

The image must be inside a position: relative container.

Overlay mocked hotspot regions using position: absolute.

IMPORTANT:
Hotspot coordinates are NORMALIZED values from 0 to 1.

Render them as percentages:

left = x * 100%
top = y * 100%
width = width * 100%
height = height * 100%

The hotspots must stay aligned with the image when the browser window resizes.

BEFORE WALKTHROUGH

On the right show:

- title
- image type
- central question
- overall summary
- a visually prominent "Big Takeaway"
- button: "Start walkthrough"

GUIDED WALKTHROUGH

When walkthrough starts:

- strongly highlight the current region
- show a clear numbered marker
- subtly highlight regions related to the current region
- de-emphasize unrelated regions if it improves clarity
- update the right-hand explanation panel

The panel should show:

- region label
- explanation
- why it matters
- relationship to highlighted related regions

Controls:

Previous
"2 of 5"
Next

At the end, show the Big Takeaway again as the conclusion.

Use this TypeScript-style data contract:

NoesisAnalysis:
- title: string
- image_type: string
- central_question: string
- overall_summary: string
- big_takeaway: string
- regions: NoesisRegion[]

NoesisRegion:
- id: string
- label: string
- x: number
- y: number
- width: number
- height: number
- sequence_order: number
- explanation: string
- why_it_matters: string
- related_region_ids: string[]
- relationship_explanation: string
- confidence: number

Put these interfaces in lib/types.ts.

DESIGN PRINCIPLES

- professional and modern
- restrained visual palette
- strong typography
- large readable explanations
- hotspot numbers clearly visible
- current region visually obvious
- related regions visibly distinct but secondary
- laptop-first responsive design
- subtle transitions are fine
- avoid excessive animations
- avoid gradients everywhere
- avoid a generic chatbot aesthetic

DO NOT BUILD:

- AI integration
- external API calls
- authentication
- database
- chat
- PDF support
- history
- export
- voice
- collaboration
- user accounts
- anything outside the scope above

Do not expand the scope.
